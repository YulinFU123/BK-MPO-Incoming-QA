不良趋势分析工作台 V9 · 公司内网版

快速开始
1. 完整解压到可写文件夹，保留所有 wheels 和 ui 文件。
2. 首次运行 环境诊断.bat，确认是 Windows x64 常规 CPython 3.15。
3. 安装依赖(免管理员).bat → 不良分析面板.bat。
4. 首次进入默认“日 / 周 / 月趋势”页。到“数据与字段”设置原表目录及文件名规则，再扫描。
5. 若使用演示数据，把原表目录设为 演示数据\每日原表；历史目录用 演示历史、输出目录用 演示结果。正式使用前改回自己的目录。
6. 可以先运行 测试趋势分析.bat；它只用临时目录和内置演示数据，不改生产历史。

这版怎么用
- 日/周/月切换：顶部三个按钮。周为周一至周日，自然月为每月1日至月底。
- 日期留空：以最新数据日期为结束日，按日回看30天、按周12周、按月12月；不是电脑当前日期。
- “最近30天 / 最近12周 / 最近12月 / 全部数据”根据最新数据日期填入范围。
- “指定员工与工序”默认折叠。展开后可以搜索、勾选多项，也可以输入完整名称后回车添加。
- “更多筛选”可选人员组、工序组、排除员工、排除工序、产品、班别、不良项目。
- 各个条件之间取交集；同一个条件的多项取并集；排除优先。
- 不选表示不限制，选了但没有匹配会显示无匹配记录，绝不自动退回全部。
- 更改条件后点“更新分析”。旧结果会出现提醒，避免把上一次结果误当本次。
- 对比维度可切换工序、员工、不良项目；TOP控制对比曲线与排行榜。图中总量始终包含全部筛选对象。
- 点击排行榜的一项，可以下钻到该对象；用“清空筛选”恢复默认。
- “保存为常用视图”保存日期、分组、员工、工序等条件；同名保存会要求确认覆盖。
- 保存的日期留空会随最新数据推进；已填写日期是固定范围，不随时间变化。
- 员工与工序分组：员工沿用“人员名单”，新增工序组可自由选择成员。一个对象属于多个组时不会重复计数。
- 重命名工序组会更新常用视图引用。删除组后仍引用旧组名的视图会匹配为空，须手动修改，不会突然扩大范围。

导出
- “导出当前趋势 Excel”输出：周期趋势、对象排行、对象趋势、筛选与口径，共4张表；包含趋势图。
- 导出的是当前趋势条件；不是旧版完整报告。
- 左侧“完整报表导出”保留原有驾驶舱、风险、改善、各筛选方案等完整 Excel 功能。
- 原有完整报表方案与新趋势页的临时条件独立；全局筛选对两者都生效。

必须理解的统计口径
1. 本页指标是“不良记录数量 pcs”，不是不良品台数。同一产品存在多条不良记录可能多次计入。
2. 不良占比是对象pcs / 筛选总pcs，不等于不良率。未取得相同范围的检查量，不能把员工/工序的数量排行解读成质量水平排行。
3. 原表如果只有不良记录，某天没记录无法判断是停产、漏导入还是零不良。因此无来源记录的日期显示缺口，不冒充已确认零。
4. 环比仅在前后两个自然周期完整且每天均有来源记录时计算；否则为“—”。基期为0时也不计算百分比。
5. 首末周期可能只覆盖所选范围的一部分；会标明不完整周期。跨年自然周使用 ISO 周年，例如 2025-12-29 属于 2026-W01。
6. 业务日期列按日期直接统计；选择记录时间模式时，才按业务日切换时间回推。全为00:00的记录也遵守该规则。
7. 未映射数量列时，每行算1；映射了数量列后，空白、非法数字、负数、无穷大将明确报错，不再默认为1。

旧版本迁移
先备份旧程序文件夹；将新版解压到新文件夹，验证成功后再使用正式数据。
可以复制自己的 config.json；新版自动补齐新增配置，不需要重做已有设置。
历史数据库、原表和结果目录可以继续指向旧位置；首次测试建议用其副本。
路径若是相对路径，移动程序后其对应位置也会改变，请到“数据与字段”核对。
本包没有你的正式 config.json 或历史数据库；不要把演示数据放进正式目录。
本版周口径与V8.1“每月1-7日为第1周”不同，旧周图数值不可直接逐项对照。
旧完整报表里的月度周表只汇总当月内的自然周片段；新趋势页可以查看跨月完整周。

代码维护说明
analytics.py：独立的筛选、日周月汇总、排行、趋势Excel导出。
ui/trends.js：趋势工作台、员工工序分组、离线SVG图表，无CDN或新增前端依赖。
engine.py：旧报表兼容、ISO周、业务日修正、数量校验、缓存键及历史写入保护。
panel.py：新增 /api/analytics 与 /api/analytics/export；串行保护数据读写。
ui/core.js：默认首页、顺序自动保存、扫描后刷新趋势、避免异步响应覆盖新条件。
selftest_analytics.py：可运行的核心回归自检；演示结果只写临时目录。

可靠性修复
配置保存使用临时文件替换；自动保存请求排队，旧响应不覆盖新状态。
生成报表期间改变配置，不再被后台任务完成时的旧配置覆盖。
扫描、预览、趋势分析、完整报表对历史库的访问串行执行。
历史先安全写入，再写日志，最后归档原表；归档同名文件不会直接覆盖。
失败导入不再永久标成“已处理”；空表会跳过；去重设置变化会使缓存失效。
报表文件名使用秒与微秒，避免同一分钟多次生成覆盖。
