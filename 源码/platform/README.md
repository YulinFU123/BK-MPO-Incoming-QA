# 异常分析平台 0.8.0-dev.1

Windows 离线融合开发候选。原异常记录台 4.5.0-rc.1 的完整业务和 BI V10.2 的 14 个页面已在同一窗口接入；原在用候选及上一版本保留，尚未替换为本平台。

0.8在单张模板设计中加入多选、组合/取消组合、六向对齐、等距分布、智能参考线和适合标签。二维码与文字整组拖动、等比缩放，字号可随缩放变化；文字支持字体、框内垂直位置和独立字号。每排默认自动计算，不固定四列。纸张支持A4/A3/A5/Letter与自定义宽高、统一或四边边距、整页及末排居中；预览、PDF和Excel沿用同一毫米坐标。见[完整操作与边界](docs/LABEL-STUDIO.md)。

二维码页面已重组为“设计单张 / 批量排版”：先拖动或按毫米设置二维码、文字和横线，再将同一模板按编号逐张生成。外框粗细、内缩、圆角、颜色和线型可调；固定文字及动态编号/名称/制作人可混排，支持撤销重做及逐条预览。自定义模板可以加密保存为常用方案，打印、PDF和Excel使用同一坐标。Excel自定义文字为可编辑绘图文本框，另保留编号清单。

“数据管理 → 二维码排版”现在按标签宽高自动选择上下或左右排列，二维码自动贴合可用区域，也能按百分比或毫米调整。名称可留空，名称、编号文字、审核栏和边框分别可选；允许按需打印重复编号。新增常用方案和本工作区自动记忆，编号只有勾选后才记住；内容独立使用Windows账户加密，不写入.eap。夹具50×50mm、热剥钳62×20mm预设保留。详见 [排版方案、操作和验收](docs/LABEL-STUDIO.md)。原业务、分析和BI继续保留，保存问题仍开放。

0.5已增加保存防护、离线变化解读和数据质量核对。Windows短暂占用时有限重试，持续拒绝则失败并保留原密文/缓存；不改变.eap格式。异常、检验数量及BI趋势分别说明变化、峰值与来源，保留原统计口径。“数据管理→数据质量核对”显示日期缺口、检验分母、原输入/唯一值规则及BI历史检查，问题优先，正常项折叠；数量问题可定位到原表行并返回原核对范围。见 [本轮方案与验收](docs/RELIABILITY-INSIGHTS-QUALITY.md)。

继续使用7个主入口，当前31个目的地含原25个、4个组织页、核对页和二维码排版页，BI14页保留。逐点标数、固定刻度、统一文本框及四主题继续保留，修正原异常图首次进入未应用新呈现的问题。布局见 [功能与布局方案](docs/FUNCTIONS-AND-LAYOUT.md)，候选见 [选择控件规范](docs/CHOICE-CONTROLS-DESIGN.md)。Windows/Electron实现适用的Apple HIG原则，不宣称使用AppKit/SwiftUI或原生Liquid Glass。

## 使用

使用交付目录中的 `程序/异常分析平台.exe`，保留整个程序目录；无需安装 Node、Python、Office、管理员组件或联网依赖。公司电脑是否允许该EXE及其子进程仍须实机验证。

1. 先查看明确标注的示例，或新建独立 `.eap` 工作区并自行设置密码。
2. “设置与备份→备份、恢复与迁移→读取原软件数据”只读解开原异常记录台数据，再复制完整表头、记录、草稿、跟进和设置。程序不获取或记录密码；用户自己在本机输入。替换当前记录前先保留完整恢复备份。
3. “复制原BI资料”用于尚未启用BI的新工作区。先正常关闭源BI软件，选择其数据目录；原目录只读保留。配置路径位于所选目录外的项目会保留原配置副本并提示重新核对，不能假装外部历史已复制。
4. 左侧依次是“工作台、快捷录入、记录查询、待办跟进、分析与报表、数据管理、设置与备份”。Ctrl+K或“查找功能”可以按名称和关键词进入全部页面及公共操作。原异常记录Excel导入、16表分析、待办、唯一值、批量扫码等没有用简化预览替代。BI日报、完整报表、配置和图表使用原引擎。
5. 导入与明细、字段校验、人员分类和统计规则集中在“数据管理”；备份集中在“设置与备份”。公共异常Excel/CSV导入、导出和兼容备份会打开原流程。扫码回车仍不直接保存，原校验不放宽。
6. 折线每个有效点直接显示数值，横线对应纵轴刻度，缺数断线；密集周期横向滚动，纵轴固定。图下可以查看完整数据表。异常趋势和帕累托仍能点击查看原明细；原Excel完整报表的图形配置保留。
7. 变化解读可展开“查看依据”；数量和BI缺数据时暂停前期比较，原异常只比较有效日期的已登记记录并说明排除项。点击来源沿用原明细和BI钻取。
8. 数据核对不会修正或删除记录。检验维度筛选不套用到原异常/BI；无日期记录的排除项按全工作区显示。BI目前只返回部分问题计数，不虚构原表行号。导入前被拒绝的记录仍在原导入预览核对。

## 数据与备份必须区分

|内容|保存位置|备份方式|
|---|---|---|
|异常完整状态、跟进、表头、草稿、新数量事实|用户选择的 `.eap` 加密文件|保存加密备份、每日备份、恢复到新文件|
|原BI配置、历史CSV、日报SQLite、归档原表、报表和PNG|工作区旁 `<文件名>.bi-data`，原格式明文|“完整备份BI目录”复制整个目录；用新工作区复制此备份恢复|
|BI配置JSON|BI目录内 config.json/.bak|原BI工具中的配置导出/恢复，只含配置|
|Excel/CSV/PNG与邮件草稿导出|用户明确使用的导出文件|普通文件，不随面板密码加密|

**面板锁不等于BI磁盘加密。`.eap`备份不含独立BI目录。** 不要单独复制EXE，不要把示例当正式数据。新平台不自动把异常条数当作不良件数，不自动推断员工不良率，也不未经配置连接公司BI。

## 开发与构建

规范源码只有本项目 `源码`：根目录41文件是受保护的原异常记录台；`bi` 是受保护的原BI73文件；`platform` 是新宿主、适配器与领域内核。运行时内的旧模块是有清单的构建快照，不作为第二份主源码。

开发测试使用 Node20+；本轮实际 Node26.10.0。Python实际验证3.12.14、pandas3.0.1、numpy2.3.5、openpyxl3.1.5，交付实际运行时。原BI包的cp315依赖锁文件保留作基线，没有用它安装或覆盖本机环境。

```powershell
cd 'D:\项目\BK_MPO来料异常跟进\源码\platform'
node --test
node scripts/check-boundaries.js
# 完整Python通道测试：将 PLATFORM_PYTHON 指向交付程序中的 python.exe
# 再运行 node --test；未设置时Python通道和Windows受控占用检查会明确标记skip。
```

离线重建工具：`scripts/build-offline-desktop.py`。提供 `--source-root`（含原41文件、bi和platform）、`--electron-runtime`、`--python-runtime`、`--output`（不存在的新目录）和可选`--node`。不执行安装脚本，不覆盖在用目录，运行时需提前在授权环境准备。

## 验证和限制

测试结果见交付测试报告及 docs/FULL-FUSION-CHECKLIST.md、docs/BI-FULL-FUSION-CHECKLIST.md。自动化覆盖与实际窗口验收分开记录。公司BI真实导出、全部业务参数组合、公司电脑策略、扫描枪、断电恢复、代码签名和长期运行尚未验收，所以此包仍为开发候选。

原0.2 `.qav`分析开发文件保持可用：使用资料/历史归档/架构开发/0.2.0-dev.1中的原文件闭环包读取。新GUI要求`.eap`；自动复制迁移入口未做，禁止把扩展名直接改成`.eap`或覆盖旧文件。

QA-WINDOWS-SAVE-001仍未彻底解决。本轮增加有上限的Windows文件替换重试，正常保存不额外等待；指定错误最多等待770ms，非暂态错误立即失败，永不先删除目标文件。600次构造保存中发生3次底层EPERM，均经自动重试恢复；最终600次成功、12次重开一致，真实Windows读句柄的短暂/持续占用场景通过。但首次随包全量152项中有1项在初始普通保存时仍失败，说明仍可能超过等待上限，不能据600次成功声称已解决。随后6进程180次并发和带观察钩子的152项复核通过，观察钩子不作为发布验收。复查失败样本未检出当前占用者，不能据此排除历史占用或断言某个进程是根因。旧失败日志保留；公司策略、断电和长期运行未验收。详见交付测试报告。
