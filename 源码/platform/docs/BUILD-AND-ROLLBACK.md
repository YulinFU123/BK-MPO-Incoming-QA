# 构建与回滚

## 离线构建

1. 从受保护源码副本建立含原41文件、bi和platform的源码根。
2. 准备已授权的Windows x64 Electron45目录、Python3.12运行时及pandas/numpy/openpyxl/dateutil/six/et_xmlfile/tzdata。以runtime-versions.json和测试报告实际版本为准，不运行原BI安装BAT。
3. 调用 platform/scripts/build-offline-desktop.py，传入 --source-root、--electron-runtime、--python-runtime、--output 和可选 --node。输出必须是新目录，工具不覆盖在用程序。
4. 执行JS全套、Python融合回归、原BI三组自检，再检查实际窗口、导出工作簿、文件清单和原始校验。构建完成不代表公司目标环境验收。
5. 规范源文件与运行快照分别校验；legacy/fusion-manifest.json、bi-ui/fusion-manifest.json记录生成交接差异。原41文件和bi73文件不能就地重写。

## 使用与数据恢复

- 正常退出后复制整套程序目录。不要单独搬移EXE。
- 保存.eap加密备份与BI完整目录备份；恢复.eap到新文件，再在尚未启用BI的新工作区复制BI备份目录。
- 复制BI源目录前正常关闭源BI软件，避免读取写入中的SQLite/CSV。
- 文件/密码格式不同会明确拒绝，不自动把旧.qav或原vault改成融合文件。

## 回滚

新融合候选未替换成果/当前版本/程序的4.5.0-rc.1。关闭融合程序即可继续原异常记录台，原正式vault路径及内容没有由本平台改写。原桌面4.4.0-rc.3仍在上一版本中。

原异常记录加密备份维持旧格式，可由旧软件恢复；完整.eap含新数量事实，旧软件不能直接读取，必须保留完整.eap原件。BI工作副本沿用原配置/CSV/SQLite/归档协议，可另复制一份用原BI验证；不得让两个版本同时写同一副本。

本轮0.8增加自由组合、居中和自定义纸张，不更改.eap格式、原保存逻辑或BI协议。上一融合0.7.0-dev.1的完整可运行目录和ZIP在轮换后保留于资料/历史归档/架构开发/0.7.0-dev.1；若原0.7仍运行，候选先停留在当前作业，版本索引不提前变更。关闭0.8后可在独立数据副本回退，历史资料不永久删除。

标签记忆独立于.eap/BI备份。0.8使用label-memory/<工作区路径SHA256>.v2.bin；若不存在，则只读导入0.7的同名.bin，首次保存写新文件，保留旧密文字节以供回退。普通数值缓存也写独立v3键，旧缓存不覆盖。记忆绑定Windows账户和工作区路径，移动工作区或更换电脑/账户不会自动迁移；不等同工作区密码保护。

关闭自动记忆不会删除已存方案；本批编号需主动勾选才记住。正式vault未解锁、写入或迁移。输出文件均为明文，打印先试一页。PDF实测纸张边长最大约0.22mm换算偏差，按0.3mm文档尺寸容差记录，不声称零误差；实际驱动、裁切和Office完整显示仍待验收。原保存故障仍开放，回滚不代表问题消失。
