当前0.6扩展：保持本方案7主入口与原25目的地，0.5新增只读核对、0.6新增“数据管理 → 二维码排版”，总计31个目的地。二维码参数左置、预览与导出右置，窄窗顺序排列；统一几何和验收见 [排版方案](LABEL-STUDIO.md)。以下保留原始归组决策，不能把历史29个目录数误读成当前数。

## 审计结果

基于0.3.1实际源码：7个原异常模块页面、14个BI页面、4个数量/安全页面，共25个导航目的地。它们不等于只有25项业务能力；原34项功能继承清单和全部BI实现继续保留。

|问题|影响|处理与验收|
|---|---|---|
|P1 顶部始终“导入数量Excel”|录入异常时容易进入不相干的数量导入|顶部最多两个与当前页有关的操作；三类导入在数据管理明确分流|
|P1 原兼容备份入口被隐藏侧栏一起隐藏|原格式备份虽有实现，融合后难以找到|公共入口调用原sideBackup，不另写备份协议；与.eap/BI备份标明范围|
|P2 按原软件来源堆叠25项|BI展开后导航过长、低频配置干扰录入|7个主入口，分析/数据/设置按任务展示；当前小组保留短二级导航|
|P2 多处重复维护路由、名称和按钮|BI页面名称缺少映射、配置名不一致，后续容易遗漏|同一功能目录生成导航、功能查找、页内入口及上下文动作，保存全部原路由ID|
|P2 数量筛选与新公共页面混用|无关页面也可能出现数量日期/维度|只有检验数量总览和明细使用该筛选；异常和BI按原口径|
|P2 窄内容区仍用宽表单结构|字段拥挤或上下层次不清|扫描独占整行；生产信息与异常内容宽窗分栏、窄窗顺序堆叠；所有自定义字段和宽度设置保留|
|P1 工作区加载尚未完成就启用导航|快速切页会被加载结束后的默认页覆盖；逐页复测发现|加载完成且会话未改变后才启用入口；浏览器回归等待实际就绪并逐页打开|

## 新结构

```text
固定侧栏                工作区：内容独立滚动
查找功能                顶部：收起侧栏 / 最多两项当前操作 / 锁定
工作台                  录入 → 查询 → 待办，常用入口集中
快捷录入                扫描识别 → 生产信息 → 本次异常 → 保存
记录查询                原过滤、全表头排序、导入与导出
待办跟进                原负责人、期限、状态与更新
分析与报表              记录条数 / 检验数量与不良率 / BI历史和报表
数据管理                导入明细 / 字段校验 / 人员分类 / 统计规则
设置与备份              显示与访问 / 加密文件 / BI目录 / 兼容备份
```

原25个目的地全部登记，BI14页不删。新增4个组织页面（工作台、分析目录、数据目录、设置目录），不替换原业务实现。当前子页面在主入口下显示同小组入口，避免全量长菜单。目录与搜索使用文本、说明和分组，不增加装饰图标或应用大标题。

## 可以共用与保留独立的功能

- 共用功能目录、导航、查找、加载/错误反馈、上下文操作、主题和选择控件。点击公共导入/导出/兼容备份调用原有按钮及校验，不复制业务逻辑。
- 统一“导入在哪儿”和“备份在哪儿”，保留异常记录、检验数量、BI日报三条原流程。
- 记录条数、检验件数和BI历史不自动混合。异常记录Excel导入仍用原字段映射；数量导入仍做显式列映射；BI沿用原数据库和配置。
- .eap备份包含异常完整状态及数量；BI目录单独备份、明文；原异常兼容备份仅供旧软件恢复。配置JSON仍不等于完整BI备份。

## 设计令牌与分配

沿用已验收的中性色与四主题：雾银画布#eef2f6、内容#fbfcfd、正文#142333、分隔#c8d2de、操作#0969c8；石墨、玻璃及高对比沿用公共令牌。Windows系统UI字体13–14px，分组标题14px、辅助说明12px；间距8/12/16/24，公共目录采用分组行而非装饰卡片。

主导航宽194px，窄预览146px；正文最多1480px但表格/录入占可用宽度。工作台与分析目录在宽窗按主内容与辅助入口约2:1分配，窄窗顺序堆叠。数据/设置以分组列表呈现，不为了对齐填空白卡片。原数量图表、表格和分页尺寸沿用；原异常表单依据子视图实际宽度分栏。

Apple HIG [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)建议控制导航占用并组织层级；[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)强调高频命令和避免拥挤。此处7入口与具体尺寸是项目设计选择，不是苹果强制值。用户要求去装饰图标，保留文本导航。未引入新框架。

评审修正：不用“把BI菜单再套一层折叠”作为本次方案；按业务任务重新归组，并用同一目录核验原功能是否能到达。两个不同口径的趋势保留独立说明，避免同名“分析”使用户误解。

## 风险与验收

- WebContentsView可能覆盖父窗口浮层；功能查找开启前隐藏子视图，关闭后恢复，保留草稿。顶部采用直接按钮，避免悬浮菜单被子视图遮挡。
- 共同动作固定白名单，不接受任意DOM选择器或脚本；等待原视图就绪并校验会话，失效请求不继续执行。
- 核验25原路由/14BI页均在目录中且可达；查找与键盘可用；原ID、字段配置、排序、导入导出、草稿、跟进和备份保持。
- GPT内置浏览器检查工作台布局、三目录、搜索/取消、不同组切换、共享动作、窄窗、四主题；自动化检查路由完整性与不允许的动作。
- 新Windows原生窗口/实物扫码枪/公司权限不凭预览判通过。QA-WINDOWS-SAVE-001保持待查，本次不修改存储实现。
