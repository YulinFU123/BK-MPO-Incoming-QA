# BK_MPO 升级分支工程约定

当前开发入口为本目录。原 `源码/platform`、原桌面 41 文件、BI 73 文件与原始 ZIP 是保护基线。当前仍有业务保存故障，不能因某次全量通过而将 QA-WINDOWS-SAVE-001 标为解决。

1. 每个新功能先定义范围、模块 ID、配置模式、保存/恢复/重置和迁移方案。长期配置使用统一模块状态服务，不能另外增加覆盖所有模块的 localStorage 大对象。
2. 新配置与正式记录、草稿、缓存分离；草稿不得自动正式提交。示例模块使用会话内存，实际工作区配置使用加密 SQLite；Windows 密钥落盘前不得确认磁盘保存。
3. 新功能必须补功能继承清单和有意义的回归用例。原扫码、动态字段、查询、跟进、导入导出、二维码排版、BI 不得用空壳替代。
4. 分析优先本地规则。责任人与报检人分开；记录条数、件数、缺陷次数与不良率分开；没有有效分母不得推算真实不良率。
5. 业务仓储、数据格式、存储路径不得就地迁移。先做副本、可回退适配、迁移校验和故障测试，再讨论替换正式入口。
6. 构建、QA 数据、截图和脚本在项目当前作业内。成果根布局及唯一版本索引遵守项目根 AGENTS.md。原版本不删除。
7. UI 在 GPT 内置浏览器复核；本机加密/入口等后端验证可以使用明确隔离的隐藏测试进程，不能因此声称可见 Windows 控件、扫描枪、Office 和公司策略已验收。
8. 当前优先级：查明旧业务保存失败 → 完成阶段 1 旧模块接入与恢复 → 导航与工作区 → 自适应导入/分析 → 视觉细节。详细继续入口见 docs/WORKBENCH-UPGRADE.md。
