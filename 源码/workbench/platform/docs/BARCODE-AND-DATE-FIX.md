# 条形码与Work Date日期修复 · 0.16.1-dev.1

基线为已校验的0.16.0-dev.1。原二维码、标签编辑、BI自由分析及旧BI14页保留，原业务格式不变。

## 日期识别

截图里的导出表包含`Work Date`、`Failure Code`、`Part Number`与`Process Type in Charge`。旧规则没有包含这些明确表头，日期因而显示“不指定”。现在加入精确别名，业务日期优先于创建日期；`Report Process Type`不擅自当作责任工序，`Failure Code Category`也不混入不良项。

使用：BI自由分析 → 数据源与导入 → 选择原来源 → 识别最新文件表头。核对“统计日期使用”的列名与样例，日期选择`Work Date`，确认映射并保存，再重新导入。日期依据该列，不取电脑当天。

重新识别时保留仍存在的手动映射，避免用户选择被默认规则覆盖。旧已确认的映射不静默改变；若原来选了创建日期，需明确改成Work Date。更改映射后重新导入才重新计算派生统计，原文件与旧批次不覆盖。斜杠月日有歧义时仍需选择日期解释方式。

## 条形码标签

入口：二维码排版 → 设计 → **添加条形码**。

- 新增Code 128条形码元素，绑定每条标签的完整编号，与现有二维码共存；不会把名称误当条码内容。
- 支持英文字母、数字、半角符号与前导零；数字连续段自动压缩编码。中文编号明确提示使用二维码，不转码、不删字。
- 位置、宽度、高度可分别调整；现有拖动、多选、组合、对齐、复制粘贴、Ctrl+D、Ctrl+右键拖动复制和撤销继续适用。
- 初始位置寻找较少重叠的区域；静区包括在元素宽度内，两侧各10模块。过窄或重叠会提示，建议按实际尺寸试印、试扫。
- 条形码仅绘制编码条；需要人读编号时使用已有“编号”文字元素，可自由排到条码下方。
- Excel包含独立可移动的条形码图片，保留二维码及编号清单。图片包保留原二维码PNG、另加条形码PNG和整页SVG；PDF/打印使用同一SVG渲染链路。
- 本次新增的是标签里的条形码对象，原每张标签保留一个二维码的规则不变；没有宣称支持只保留条形码的自动版式。

## 记忆、兼容和回退

含条形码的模板使用version 2，原version 1二维码模板可继续读取。排版记忆写到独立`.v4.bin`、schemaVersion 3；旧`.v3.bin/.v2.bin/.bin`只读继承并保留字节，旧版不会接收到无法识别的条形码模板。关闭“记住本批编号”仍不保存本批编号；命名方案不带本批正式数据。

正常关闭新候选即可回退完整0.16.0-dev.1包，继续使用旧v3记忆；新条形码设置在新版v4记忆中保留。不得覆盖唯一业务文件或删除恢复备份。
