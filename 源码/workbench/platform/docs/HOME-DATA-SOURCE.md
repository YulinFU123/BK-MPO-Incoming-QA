# 0.14.0-dev.1 首页主要数据源

基于0.13.3-dev.1增量实现。进入工作区后的首页新增“首页主要来源”，默认自动选择；无需先建立人工异常记录才能分析BI。旧记录页加载修复、统一主题、二维码、扫码、字段与BI筛选导出继续保留。

## 使用

1. 在原BI模块完成日报导入或历史数据配置，然后回到工作区首页。
2. “首页主要来源”可选自动、BI主要统计、人工异常记录。自动优先选当前范围有效的BI；没有可用BI时显示人工记录，并说明原因。明确选BI时，读取失败或无来源不会偷偷显示人工统计或假零。
3. “BI来源类型”支持自动、日报、历史。自动有日报时优先日报；两套系统的数据不相加。多个日报来源范围必须明确选择一个，以免重叠数据重复累计。日报采用原快照的当前有效版本及Rework/Scrap口径，历史沿用原BI全局筛选。
4. 可筛工序、不良项、报检班别、BI责任员工及搜索。跟进负责人、报检人、原记录状态等人工专属条件不能套在BI上，界面会提示，不会忽略条件后仍显示全部BI。
5. 旧日期数据可点“全部”。首页会纳入BI实际日期范围；其余日期选择保留用户设定，不随意改成最新一天。

## 同时有两类数据

BI主要展示缺陷数量pcs、来源行数、数量趋势、分类/工序/BI责任员工/报检班别分布和BI明细；人工记录条数、未关闭、超期单列并仍可点击查看。BI责任员工与人工跟进负责人独立筛选。

例如BI为100 pcs、人工登记5条：分别显示100 pcs和5条，不生成105件。共同SN不会让任意一侧的数据被删除。相同SN可存在多个不同缺陷，本轮不以SN跨来源合并。

BI数量是源记录数量字段之和，可能包含同一产品的多次不良，不等于去重的不良产品件数。没有核实且匹配的检验分母时，不计算BI真实不良率。

## 明细、图表与更新

BI图表每个点保留数值和刻度，缺来源的周期为缺失，不填成已确认的零；只有前后来源日期完整时才进行同期比较。点击图表可查看对应来源明细，包括空值类别。编号、SN按原文本显示。

“导出当前明细”跟随当前主要来源：BI导出BI明细CSV，人工模式沿用原记录导出。导出前核对来源修订；分页不改变汇总与导出范围。首页BI CSV最多25000行，更大范围仍可用原BI完整报表导出。BI首页读取上限25万行，耗时计算由原独立Python进程执行；日报按来源文件修订缓存解析，来源替换后失效。

日报新增/替换、BI扫描、联动接收或BI目录导入会通知首页刷新。首页只读分析与自动保存配置不再发更新通知，避免循环刷新。外部直接改动源文件后，使用原BI扫描或首页刷新读取。

## 独立记忆、重置与兼容

新增模块`module:home-data-source`，保存mode、channel、dailyScope、employee。沿用原模块状态服务，实际文件位于用户配置目录的`ExceptionAnalysisPlatformPreview/workbench-state-v1/modules.sqlite`，内容经现有Windows账户保护加密，工作区键由实际文件路径派生。切换文件/工作区相互隔离，示例仅在会话内。

“配置记忆”中选择“首页数据来源”，可保存命名方案、查看历史、单独重置、备份与恢复；默认auto，不覆盖旧分析布局和草稿。同一实际工作区内的首页分析标签共用来源选择，筛选和布局仍分别记忆。

没有修改业务数据库、加密仓储格式、数据路径或原BI73文件。回滚旧程序时新增模块设置被忽略；不要把新模块的配置备份强行导入不认识该模块的旧程序。原候选与业务备份均保留，不就地替换正在运行的窗口。

## 边界与尚未实现

- 工作区管理卡片和侧边预览仍显示人工记录及检验数据，现已明确标注；打开工作区后的首页提供本轮BI优先分析。没有静默扫描所有关闭工作区的BI并汇总。
- 本轮通过不相加避免跨来源重复统计，没有自动建立人工记录与BI事件的永久关联，也没有删除任何疑似重复业务行。后续关联需稳定业务唯一编号及明确确认，不能仅凭SN推断。
- 原“检验数据集”保留原有口径，没有当作BI缺陷明细混入新来源通道。
- 实际界面、公司现场数据、原生控件、打印和目标权限仍未验收。GPT浏览器权限由组织策略锁定，未尝试改地址或使用其他浏览器绕过。
- 代码/模型、合成Excel、配置隔离测试不代表正式验收。历史保存故障QA-WINDOWS-SAVE-001仍开放，正式放行为否。

完整回归、随包专项、Python集成及原文件校验结果，以本轮放行检查和测试原始日志为准。

## 本轮回归发现

末轮340项代码回归中339项通过、1项失败：原`storage-failure`的写入失败后重试用例，Windows在替换文件时返回EPERM。诊断显示临时文件和目标文件存在、为普通文件且非只读；尚未确定具体拒绝原因。单项诊断重测通过，不能据此抹去全量失败或宣称原保存问题已解决。

本轮未修改原加密仓储实现。来源选择、状态隔离、图表模型与其余回归通过；新BI首页13项合成Excel集成和原导出/接收18项集成通过。候选仅供核验，正式不放行。
