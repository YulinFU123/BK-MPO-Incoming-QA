# BK_MPO 智能异常管理工作台：完整优化与实施计划

计划版本：1 · 2026-10-29。执行基线为已交付的 0.9.0-dev.1，演进来源为完整融合的 0.8.0-dev.1；原桌面 4.2/4.5 和 BI V10.2 是兼容与继承基线。

本计划中的“待开发”不是已实现功能。开发副本为 `源码/workbench`；已交付程序、原 ZIP、业务库和用户配置不覆盖。本轮先完成保存故障的诊断与保护增量，后续按验收门槛逐步交付。

## 二、现在已有的能力与尚缺部分

- 已有：原异常新增/编辑/查询/跟进、动态字段、扫码与防重复、批量暂存、Excel/CSV、密码/备份；二维码设计与批量排版；原 BI 14 页接入；数量/率分析和明细投影。
- 0.9 已有：全局外观/侧栏、上次页面、数量分析条件、投影查询条件及页面记忆；加密配置 SQLite、命名方案、修订恢复；草稿服务接口。旧模块尚未全部接入。
- 当前缺口：保存间歇故障仍开放；旧草稿和二维码/BI 仍部分使用各自机制；稳定工作区与模板版本、自动导入/分析尚未形成完整闭环。
- 不宣称：当前所有数据已统一加密。BI 工作目录仍独立明文，不包含在 `.eap` 备份中，后续备份设计必须明确提示边界。

## 三、记忆与数据架构

沿用 Electron + HTML/CSS/JavaScript、原 Python BI、现有仓储适配与 `node:sqlite` 配置服务；不为外观引入 SwiftUI/WinUI，不就地把业务库转成 SQLite。

依赖方向：界面 → 模块应用服务 → 领域模型/端口 → 存储或文件适配。旧页面逐个通过适配器接入，不能用新空表单替换完整旧实现。

|对象|作用域及记忆内容|保存/恢复/重置要求|
|---|---|---|
|全局|主题、窗口尺寸位置、侧栏、收藏、快捷键|用户本机；启动恢复；单独重置布局；不涉及密码|
|工作区|模板、分类、打开标签、专属快捷入口|稳定工作区 ID；关闭标签只改变打开状态|
|录入/扫码|模板默认值、输入顺序、唯一值规则、扫码解析|工作区+模块+模板；扫码回车不提交；草稿与正式记录分开|
|查询/跟进|列顺序/宽度、排序、筛选、页容量|长期布局与临时搜索/选中/滚动分开；记录删改后校正失效引用|
|二维码|命名模板、纸张/可打印边界、尺寸、间距、边框、文字开关、组合/居中|工作区+标签方案；逐项校验打印溢出；旧 v2 记忆先只读导入并保留回退；编号队列与模板参数分开|
|BI/分析|数据源映射、指标/维度、班次、图表布局、时间方案|工作区+来源+方案；相对日期按当天解析；不保存解密密码|
|页面/草稿|未提交输入、编辑对象、焦点/滚动等必要状态|明确恢复/放弃；草稿不自动转正式记录，模板变化时提示不兼容项|

优先级：系统默认 → 全局用户选择 → 模块默认 → 工作区模块配置 → 当前临时状态。每个模块声明 schema/version、默认值、迁移、保存/恢复/重置策略和回归测试。

配置写入使用版本比较，失败保留未保存状态；普通操作防抖，关键业务显式提交。窗口关闭/锁定前完成必要冲刷，失败不能悄悄退出。新旧记忆迁移先在副本上比对数量与字段，成功后才切换读取来源，旧文件保留。

## 四、主界面与组件改造

布局按“稳定导航—工作区标签—当前内容—保存/进度反馈”组织。内容页提供一个明确主操作，低频功能收进对应管理页，不继续往一级导航堆按钮。

- 工作台：工作区总览、最近打开、收藏入口、待处理摘要。
- 异常记录：快捷录入/扫码、列表、跟进、批量处理与历史查询。
- 智能分析：总览、趋势、分类/帕累托、班次/工序/人员维度、预警、自定义看板。
- 管理中心：工作区、模板/字段、导入导出/映射、规则、二维码模板、配置和备份。

以上分类必须映射旧入口，保留二维码独立直接访问能力。原 BI 页面逐项登记，不因重分组消失。

统一设计令牌与组件：字体层级、间距、边框、对比色、行高、按钮、可输入下拉、日期/数字/多选、表格、对话框、焦点和状态提示。采用克制的深色导航与清晰工作区，避免大片无层级纯白；具体颜色是项目设计选择。页面不重复堆标题、图标和解释；必要字段标签、表头、图表轴和窗口控制必须可识别。

下拉框重点验证：已输入仍能打开/搜索/选项；上下键与回车只选择选项；弹层不被裁切；选中/禁用/空结果/长文本清晰；缩放与小窗口定位正确。扫描枪回车与“保存记录”命令分开。

UI 参考 Apple HIG 的层级、布局和反馈、Fluent 的桌面操作原则，不能把参考当成必须模仿 macOS。界面验证在 GPT 内置浏览器；原生窗口控制、DPI、打印和实际扫描枪必须另列目标环境测试。

## 五、分析必须让人直接看懂

1. 先统一口径：记录条数、不良件数、缺陷次数、构成占比分开；没有有效产量分母显示“无法计算真实不良率”。责任人与报检人是不同字段。
2. 首屏显示本期数值、可比较的上期数值、增减绝对值、变化幅度及有效数据覆盖；上期为零等情况不制造无限增长率。
3. 趋势图显示时间轴、单位、数值刻度、水平参考网格；可显示各点数值，密集时提供缩放/滚动与完整数据表，避免重叠。悬停与键盘查看同等可用。
4. 日/周/月和业务班次统一时间定义，夜班跨午夜按已配置业务日汇总；缺失数据与真实零分开。
5. 排名、帕累托、班次/工序比较可钻取对应明细；筛选后的图、表、导出同一口径。
6. 预警显示触发阈值、基准期、样本量和关联记录；不从人员记录数量直接推断责任。
7. 摘要使用真实数值和离线规则，区分事实、统计关联与待核查原因。分析后端缓存按数据变更和筛选失效，不无条件扫描全部历史。

## 六、智能导入、模板与工作区的实施细节

- 表头识别允许标题、说明和空行；多个工作表分别预览。别名、类型、来源和已确认映射综合匹配，低置信度须确认。
- 映射规则按来源指纹与模板版本保存。结构变化时重新预览，不仅靠文件名复用。
- 导入批次保存来源指纹与业务唯一键；重复文件/行提供结果预览和处理选择，不静默重复统计或删原数据。
- 模板字段用稳定 ID，名称可改；删除/改类型保留历史定义或明确迁移。模板配置保存与正式发布分开。
- 工作区区分数据所属空间与筛选视图。同一记录的多个视图共享稳定记录 ID；全局汇总不重复。
- 复制工作区默认只复制配置。复制业务记录必须单独明确操作，不混入普通标签切换。

## 七、每批验收与发布治理

每批都包含：需求映射、真实修改清单、数据/状态作用域、自动化与实际操作结果、失败记录、未测项、回退入口。测试包括原来的扫码、重复拦截、动态字段、查询排序/序号、跟进、Excel 导入导出、密码备份、二维码排版/打印和 BI 接入。

重点门槛：失败保存原字节不变且缓存不误提交；锁定/关闭与排队写入不交叉；两个工作区独立；重启与异常退出恢复；损坏配置不破坏业务；重复导入不累计；汇总可追溯；中文路径/长文本/高 DPI/离线普通用户可用。

发布分三级：源码开发增量 → 可测试开发包 → 目标环境验收后的正式包。构建成功、语法检查和某一轮全过都不能替代完整验收。统计已通过、已失败、未测试、环境限制分别列出。

成果目录保持现有当前/上一版本布局，版本索引唯一；历史作业归档、不删除唯一原件。升级包与数据分开，先验证旧包可独立恢复，再讨论版本轮换。当前 0.9.0-dev.1 包和主 4.5 候选保持可用，0.9.0-dev.2 未打包前只标源码开发中。

## 八、本轮推进范围与下一次入口

本轮：建立 0.9.0-dev.1 校验快照和归档；制定本计划；为业务原子保存补充不泄露内容的阶段诊断与回归，执行 Windows 受控占用和保存压力测试；据结果确定修复路径。

随后：保存问题达到门槛后，首先接入旧录入草稿与查询/跟进状态，再迁移二维码和 BI 配置；不能绕过可靠性直接扩展大量新页面。若保存根因仍不能确定，继续交付诊断工具、证据和保护增量，故障状态保持开放。
