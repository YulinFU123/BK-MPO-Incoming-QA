# 产品类型与工序名称修复 · 0.20.1-dev.1

## 直接修复的位置

原版本已改新文件的导入推荐，但首页下拉框、图表和明细仍把内部分类字段固定显示为“工序”。旧数据中的LCD、MMC、MMC24、MPO因此继续被错称为工序；要求用户重新配置并没有修复这个显示问题。

现在按已保存字段和实际分类值返回分组语义。Process Type in Charge或Report Process Type确认都是MPO/MMC/LCD系列时，显示“产品类型”；Product Type、Product Family等明确产品字段也使用产品名称。Workflow Step、中文工序以及实际内容为装管等操作的旧Process Type字段保留“工序”，不全局替换所有工序文字。

首页对应下拉框、图表标题、图表设置、BI明细、CSV、工作区管理预览、自由分析维度与筛选、分析板块及Excel明细使用一致名称。产品类型不冒充真实工序来匹配产量计算不良率。

## 使用方法

正常关闭旧窗口后打开当前版本，回到原BI工作区即可。已选的MMC/MPO、原日期、员工筛选和分析方案继续有效；无需为本次名称修复重新导入、重建或搬动已有数据。

本次不自动改写映射。若要改成真正的责任工序，在数据源把“分类字段（工序／产品类型）”选择为Workflow Step in Charge；报检工序为Workflow Step Name。实际修改映射或班次后仍需确认并重新读入，以免旧数据口径冒充新口径。

已有自定义报告文字不被擅自重写；`{维度}`自动显示产品类型或工序，旧`{工序}`占位符继续作为旧分类别名保留兼容。

## 数据和配置保护

本次为只读语义适配：稳定字段ID、原分类筛选键、数据库、原始文件、配置及数量保持不变。新语义只放在查询响应中，没有迁移正式记录，也不创建新配置文件。

分类依据完整已导入分类值，不能因选中MMC、日期改变或当前页只有一条记录就误变名称。无法确认的旧模糊列保留原名，不根据单个值猜其他字段。员工与报检人仍独立，不改数量和班次口径。

单类来源的Excel明细用“产品类型”或“工序”；混合来源使用“分类（产品类型／工序）”，保留来源列。旧BI独立通道缺少字段元信息时沿用原标签，不冒称已全部统一；本轮重点修复原生BI自由分析及其首页、管理页投影。

## 验证与回滚

回归覆盖截图四个选项、MMC选择保持、已有数据无需重导、图表和明细同名、真实工序不被误改、Excel实际表头和数值，以及禁止产品类型冒充工序分母。

测试使用合成工作簿、真实SQLite/原生进程、实际Excel导出和DOM模型；本机BI只读核对，不写入用户资料。实际Windows可见界面、公司电脑、扫描枪和打印未验收；QA-WINDOWS-SAVE-001仍开放，当前为开发候选。

回退前关闭程序并保留资料备份，启动上一版0.20.0-dev.1。数据和配置未迁移，上一版继续使用其固定旧标签。
