# 0.13.3-dev.1 异常记录页面空白修复

用户反馈：0.13.2选择记录查询后内容空白，重复提示“操作未完成，请检查文件、数据或权限”。本轮以0.13.2源码及随包宿主为基线，没有读取或改写真实业务记录。

## 可复现的加载缺陷

`insight-summary.js`末尾的赋值表达式会返回一个包含`create`函数的对象。原宿主把脚本执行结果传回主进程，无法序列化该对象。0.13.2等待完整初始化后才显示页面，而失败的加载任务持续被复用，因而重复选择仍无法显示。

本轮测试将实际摘要脚本放入独立JavaScript上下文执行，并加入结构化克隆检查：原脚本得到`DataCloneError`，修复后结果为`undefined`，页面中的摘要功能对象仍存在。将同一返回值检查接入模拟宿主，0.13.2原宿主1项预期失败，修复宿主通过。它验证了代码缺陷，与用户截图症状一致；没有冒充目标窗口的现场重现。

依据：[Electron官方executeJavaScript接口](https://www.electronjs.org/docs/latest/api/web-contents#contentsexecutejavascriptcode-usergesture)说明执行结果会作为Promise结果返回；[Electron实现](https://github.com/electron/electron/blob/main/lib/browser/api/web-contents.ts)通过IPC调用页面执行。这里的故障判定来自本地实际脚本与返回值测试。

## 修改

- 新增`desktop/embedded-scripts.js`，仅用于本程序同步初始化脚本。执行后显式结束为`undefined`，不改变全局声明、函数注册及原业务返回接口。
- 原始脚本异常仍然抛出；没有通过吞掉错误伪造加载成功。
- 记录页初始化失败时释放未显示成功的页面，保留控制器及业务存储，允许再次点击菜单重新加载。
- 失败提示说明发生在哪个初始化阶段，不再一律暗示是文件或数据权限问题。
- 修正宿主测试：除了模拟执行，还检查实际摘要脚本的返回值能否跨进程传递。上次主题测试未覆盖这一点，属于漏检。

## 功能继承与数据保护

保留0.13.2统一主题、0.13.1指定不良项筛选导出、二维码编辑、扫码、动态字段、记录查询与跟进。没有改数据库格式、存储路径、加密仓储、用户配置或原BI源码。不需要迁移数据，也不需要创建新工作区绕过问题。
