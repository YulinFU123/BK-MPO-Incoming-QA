## 阶段 1 已完成的可运行闭环

|作用范围|配置内容|当前接入|恢复/重置|
|---|---|---|---|
|全局 `shell`|主题、紧凑行高、侧栏宽度、主动折叠|实际主界面|启动自动恢复；配置面板单独重置|

|模块 `analysis`|数据集、日期、筛选、数量/不良率图|实际数量分析与共用数量筛选|自动恢复、命名方案、单独重置、20 个修订历史|
|模块 `query`|来源、页容量、字段排序|实际数量/异常投影明细|自动恢复、方案、单独重置；原业务查询原实现保留|
|页面 `query/main`|搜索、页号、滚动|实际明细页面|与长期排序分开，重新加载恢复|
|草稿 `records`|模板 ID、编辑 ID、字段值|服务接口/事务/重启恢复测试；未替换旧录入 UI 的 `pendingUI`|显式清除生成空草稿修订，不会自动正式提交|

配置面板显示可理解的字段摘要，支持查看保存状态、保存当前方案、把当前配置另存为新方案、应用方案、单模块重置、恢复历史、完整配置备份、从备份恢复当前模块、检查配置库与重试。方案最多 12 个；每个配置保留最近 20 个修订。方案不包含正式业务记录、密码或扫码队列。

用户主动修改后按约 350ms 防抖写入；修改过程有“待保存/正在保存/已同步/未保存”状态。关闭或锁定前冲刷队列，失败保留未保存内容并阻止静默退出。切换会话时检查会话代次；冲突使用修订号拒绝覆盖。未改动值不产生新的写入。存储在线程中执行，不在 UI 线程等待 SQLite 文件锁。

数据存在普通用户目录：

`%APPDATA%/ExceptionAnalysisPlatformPreview/workbench-state-v1/modules.sqlite`

SQLite 中保存加密 BLOB、不可读的作用域哈希、修订号和时间；使用 Windows 异步 safeStorage。**该保护依赖当前 Windows 账户和原用户配置中的提供器密钥，不等于跨电脑便携加密备份。** SQLite/WAL 放本机目录，拒绝直接 UNC 路径；映射盘和公司文件重定向还需目标环境测试。

作用域键来自：宿主工作区文件路径哈希 + 范围 + 模块 ID + 页面 ID + 模板 ID。渲染端不能提交任意工作区路径；模板 ID 不同互不覆盖。当前仍受路径绑定限制，移动文件不是稳定工作区 ID 迁移，阶段 3 必须处理。

## 技术决策依据

- [Electron safeStorage 官方 API](https://www.electronjs.org/docs/latest/api/safe-storage)：异步加密与 Windows 账户保护边界。
- [Node SQLite 官方 API](https://nodejs.org/api/sqlite.html)：随包 API，事务、备份、只读连接。项目实际支持性由上述运行时测试确认。
- [SQLite WAL](https://sqlite.org/wal.html) 与 [synchronous](https://sqlite.org/pragma.html#pragma_synchronous)：本机 WAL、FULL 同步、在线备份；网络共享不适合作为本配置库位置。
- [Apple HIG 布局](https://developer.apple.com/design/human-interface-guidelines/layout) 和 [Fluent 2](https://fluent2.microsoft.design/)：沿用清晰分组、统一焦点和渐进展开。面板的配色/宽度是本项目设计选择，不是官方强制尺寸。没有引入 SwiftUI、WinUI 或新的组件依赖。

首次密钥落盘门禁来自本轮失败/复测证据，是项目防护措施，不是将个人实现冒充官方要求。仍需持续关注提供器轮换与系统故障场景。

示例模块配置现为会话内存，不写入长期配置库；全局外观仍按用户选择记忆。二维码沿用原记忆协议并共用密钥落盘防护。补充了冲突后明确放弃未保存界面配置再重读的入口，以及锁定清理和嵌入视图遮挡保护。当前日期范围保存为明确起止日期，动态相对日期方案在后续阶段实施。
