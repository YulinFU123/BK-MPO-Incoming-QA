# 工作区来源与首页数据联通 · 0.18.0-dev.1

本版基于现有0.17.0-dev.1增量修改。新增工作区时必须选择“手动录入不良”或“BI导入不良”，无需创建密码。来源选择是工作流程和统计范围，不是权限控制。

## 创建与调整

1. 工作区管理 → 新建工作区 → 填名称、工序 → 选择主要数据来源 → 创建。
2. 手动录入工作区默认使用录入与人工异常统计；进入BI自由分析的入口会引导返回人工分析。
3. BI工作区使用本工作区BI来源和分析；快捷录入入口会引导进入BI自由分析。
4. 旧工作区保留“沿用旧来源设置”，不自动搬动数据。可在工作区管理 → 选择卡片 → 基本信息中改变主要数据来源，然后重新打开工作区。
5. 选择来源不会合并、删除、复制或转换任何业务记录。复制工作区仍只复制现有录入模板和相关配置，不会复制BI下载目录、BI配置或正式记录。

## 为什么导入了，首页没有数据

此前BI自由分析使用工作区旁的`<工作区文件>.analysis-data/analysis-v1.sqlite`，首页只读取旧BI日报/历史模块；两条读取路径没有接通。本版首页“自动”优先读取当前工作区的BI自由分析数据，只有该来源为空时才尝试原BI模块。不会把两套BI数量相加。

本次只读检查发现，一个已有派生分析库有1,919条、业务日期均为2026-10-16；另一个工作区的派生库没有数据。切换工作区或查询其他日期不应显示这1,919条。首页现在显示可用日期和总行数，并提供“查看全部BI日期”按钮。没有来源覆盖的日期保持缺失，不当作零不良。

原工作区如保存了“仅人工记录”或指定的旧BI日报/历史通道，兼容设置仍保留；请先在基本信息选择BI，再在首页的BI来源选择“BI自由分析”。有多个BI来源时请在BI自由分析页明确选择一个来源。

## 保存、恢复与隔离

|对象|保存与恢复方式|
|---|---|
|工作区主要来源|加密工作区目录`managed-workspaces-v1/catalog.sqlite`中的条目外层`dataSourceMode`；按稳定工作区ID隔离，允许auto/records/bi|
|首页通道和人员筛选|原`home-source`模块记忆；显式工作区来源优先于旧首页mode，其他选项继续恢复|
|导入BI明细|原工作区旁`.analysis-data/analysis-v1.sqlite`；只读投影至首页，不另存正式记录|
|自定义板块、方案、日周月查询|继续使用`.analysis-data/analysis-panels.settings.json`；本次不迁移|

旧目录没有该字段时按auto恢复，修改不改变目录schema1或原EAP加密格式。旧版本可忽略外层扩展字段。模块重置不改变工作区主要来源；在基本信息中可以改回沿用旧设置。工作区完整备份继续包含目录条目的来源选择；派生BI数据、板块设置仍需依原说明单独备份。

## 统计边界与名称

- “缺陷数量”在活动平台界面及本地分析导出改为“不良数量”；字段ID、统计公式和数据格式不变。
- “二维码排版”改为“夹具标签制作与排版”，保留二维码、Code128、编辑、快捷键、排版和导出；搜索“二维码”仍可找到引导。
- BI不良数量与人工记录条数永不相加；明确BI工作区只展示BI数量和BI明细指标，不展示人工零值指标。
- 事件次数和经确认的去重件数仍区分为“次/件”，不会仅因改名变成唯一不良件数。
- 首页本轮不计算不良率。BI自由分析仍需有效的日期＋工序＋班次产量匹配，不能从明细行数推算产量。
- BI责任员工与报检人独立筛选；不支持的人工跟进条件会明确提示，不能静默忽略后显示BI总数。
