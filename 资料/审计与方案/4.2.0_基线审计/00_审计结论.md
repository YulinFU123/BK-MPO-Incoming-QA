# 异常记录台 4.2.0 基线审计结论

审计记录：2026-10-25；报告整理与最终校验：2026-10-26。范围：只读检查用户指定 ZIP、独立副本运行验证、UI 诊断及改造计划。**没有改写应用源码、原始 ZIP、正式业务数据或配置，没有发布新程序。**

## 结论

4.2.0 可以作为后续改造的可追溯基线，但本轮不将它重新认定为已通过目标公司电脑验收的正式版本。

| 项目 | 本轮结果 |
|---|---|
| 原始 ZIP | 实际可访问，158,334,551 字节；100 个文件；解压后 374,340,101 字节 |
| 完整性 | CRC 通过；内置 24 个源码文件校验全部一致；新增全包文件 SHA-256 清单 |
| 实际技术栈 | Electron 45.0.0、Chromium 156.0.8078.48、原生 HTML/CSS/JavaScript |
| 原有回归 | 在 ZIP 新解出的 EXE 上重新执行，92 项通过 |
| 补充专项 | 6 项断言：3 项通过、3 项失败；另做 20 个页面/视口布局观测和单次 1000 条合成数据测量 |
| 启动和恢复 | 当前 Windows 11 测试环境可启动；实际退出进程、重开后恢复 1000 条审计测试记录 |
| UI 主要缺陷 | 按钮 Enter 被拦截、主按钮文字对比度不足、表格焦点过多、处理结果文本框过窄 |
| 发布缺口 | 原 ZIP 不含测试脚本、构建脚本和原始测试证据；EXE 无数字签名；目标公司环境仍未验收 |

原始 ZIP SHA-256：

`76424238d746a201911f824992801bcb8b097f463c0fe47e259b528e5e2f1ec2`

## 最值得先处理的事项

1. 修正 Enter 的事件范围：保留扫描输入框“不提交”，恢复焦点位于按钮时的标准 Enter 激活行为。
2. 修正主按钮颜色：实际白字蓝底对比度约 4.02:1，13px 普通文字未达到 4.5:1 的参考门槛。
3. 优先优化记录列表：1000 条记录生成 12,000 个单元格和 16,011 个可聚焦元素；整条记录查看、操作区、键盘导航需要一起整理。
4. 统一处理弹窗：当前宽弹窗中的“处理结果”仍是很窄的多行框，明显不适合填写跟进结果。
5. 补齐发布证据：源码、测试、构建、原始结果和回滚步骤必须与候选产物关联，不能仅凭“打包成功”发布。
