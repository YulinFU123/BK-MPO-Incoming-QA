# 基线、项目结构与功能继承

## 1. 检查对象与保护方式

原件：`D:\项目\BK_MPO来料异常跟进\成果\异常记录台_4.2.0_最新版.zip`。

使用只读 ZIP 操作进行 CRC、逐文件散列和目录检查。运行副本位于项目的 `验证/基线审计_4.2.0/运行副本`，测试使用 `--quality-qa --qa-data=<独立测试目录>`。没有读取正式用户 vault，也没有把测试数据放入正式数据目录。

检查结果：100 个文件、24 个应用源码/资源文件；源码校验无差异，全包没有相同内容散列的重复文件。没有发现名为 vault.json 的用户数据、数据库或业务备份。该结论来自文件目录及应用文件检查，不是对每个二进制内容进行敏感信息取证。

只找到一套业务应用源码 `resources/app`，没有嵌套的旧版业务 ZIP。`resources/default_app.asar` 是附带的 Electron 默认应用资源；`底座质量记录台_wer.dll` 保留旧名称，不能据此判定存在另一套完整业务版本。本轮都没有删除。

## 3. 模块边界与现状

| 模块 | 已承担职责 | 审计判断 |
|---|---|---|
| main.js / preload.js | 创建窗口、IPC、网络限制、锁定、数据目录 | contextIsolation=true、nodeIntegration=false、sandbox=true；IPC 检查来源；保留此边界 |
| vault.js | scrypt、AES-256-GCM、密码、原子写入/恢复 | 有独立模块和专项测试；UI 改造不应顺带更改格式 |
| daily-backup.js | 每日第一次保存后的完整加密快照 | 临时文件、fsync、重命名；不能误当每次保存都更新的最新备份 |
| renderer.js | 模板、记录、筛选、导出、处理、历史、草稿及大量事件 | 89,821 字节，职责集中；已有拆分但还不是完整业务层分离 |
| record-rules / input-rules / fill-rules | 导入查重、字段规则、条件补全 | 可复用纯规则基础；保持字段 ID 及文本语义 |
| combo-box / input-policy-ui | 候选选择和输入规则界面 | 已有键盘逻辑；仍受外层表单 Enter 捕获影响 |
| workspace-ui | 菜单归组、设置页签、外观和滚动 | 按中文 h3 文案分配设置页签，存在文案与结构耦合 |
| xlsx-reader / xlsx-import-ui | ZIP/XML 读取、映射和导入预览 | 不执行公式，只读缓存结果；有文件/行/列/解压限制 |
| CSS | 明确 foundation → components → workspace 层 | foundation.css 29,469 字节保留大量旧规则，后层覆盖仍较多；设计令牌尚未覆盖所有尺寸与状态 |

数据流：UI 事件 → renderer 状态/规则 → preload 暴露接口 → main IPC → Vault → 本地加密文件。保存及备份使用 sendSync；写盘和部分加密同步进行。1000 条本轮测量较快，但不能据此保证大规模场景不会阻塞。

## 4. 页面与组件清单

主页面：密码/解锁、快捷录入（新增与修改共用）、记录查询、趋势分析、待办看板。

设置：基本信息、字段与校验、自动填写与分析、数据管理四个页签。

弹窗/临时层：输入规则、Excel 导入映射、批量扫码、异常处理、修改历史、密码与自动锁定、通用文本/密码提示、候选菜单、更多操作菜单、原生确认对话框。

不存在独立的“整条异常详情页”；已有单元格查看、修改表单、处理弹窗和历史文本。不存在分页、虚拟列表、框选多条删除或自动深色主题。不得把这些列为已经继承的功能。

## 6. 数据兼容性红线

- 正式路径仍为 `%APPDATA%\QualityDeskOffline\vault.json`；每日快照在同目录的 `daily-backups`。
- 外层加密标识 `quality-desk-encrypted-vault`、版本 1、scrypt-32768-8-1、aes-256-gcm 和 AAD 不变。
- 业务 state.version=1。templates、columns、records、values、workflow、history、deletedRecords、pendingUI、batchDraft 等已有字段须保留；未知可选字段不能随 UI 清理丢弃。
- 唯一值、旧日期归一化、序号显示与永久记录 ID 是不同概念，必须分别验证。
- 旧记录可能不满足后来增加的规则：展示和备份不能清洗历史；编辑/导入行为须保持明确提示。
- 外观使用 localStorage，备份未承诺携带该偏好；不能把外观未恢复误判为业务数据丢失。

## 7. 构建与发布现状

原 ZIP 包含可运行环境和必要源码，但不含 README 所引用的验证脚本、构建脚本、测试工作簿和原始测试日志。当前项目目录另有 build_release.py，它依赖已经存在的完整运行目录，主要执行复制、打包和校验，并非从干净环境下载固定运行时后构建的完整流水线。

该脚本允许相同版本路径覆盖，测试门槛只搜索日志中的成功文字，日志未绑定被测源码散列。这些都是后续应补齐的发布治理问题。本轮没有运行发布脚本，也没有沿用此前“最多两版”的删除约定；按最新指令保护原件和历史资料。

EXE Authenticode 检查为 NotSigned。这不等于当前电脑不能运行，但公司设备是否允许运行尚未验证。
