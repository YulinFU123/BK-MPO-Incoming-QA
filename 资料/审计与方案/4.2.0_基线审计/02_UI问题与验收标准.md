# UI 问题与验收标准

版本：4.2.0 基线；报告日期：2026-10-26。以下区分实际失败、截图诊断、静态风险和新增建议。严重程度 P1 表示优先处理，P2 表示随后改善；与实施阶段的 P0/P1/P2 页面顺序不同。本轮未确认造成业务数据丢失的 P0 缺陷。

| 编号 / 级别 | 问题与证据 | 影响及改进方案 | 验收标准 |
|---|---|---|---|
| UI01 / P1 | 实测：焦点在保存按钮或下拉展开按钮时，Enter 被表单捕获，转到 SN；保存数仍为 0，下拉仍关闭。`renderer.js` 的表单 keydown 范围过宽 | 防扫码误提交应针对输入行为，不能把标准按钮激活一并取消。区分输入框、组合框、按钮、多行框和中文输入法组合态 | 扫描 SN 后 Enter 不保存；按钮 Enter/Space 正常；下拉键盘选择有效；多行框 Enter 换行；中文候选确认不提交；Ctrl+Enter 仍经过全部校验 |
| UI02 / P1 | 实测：主按钮白字配 #007AFF，13px/500，对比度 4.01698:1 | 调整主色及悬停/按下状态，保留统一蓝色语义。采用普通文字 4.5:1 的验收门槛 | 默认、悬停、按下状态普通文字均 ≥4.5:1；焦点可见；不能仅靠颜色区分状态 |
| UI03 / P1 | 实测 1000 条记录有 12000 单元格、16011 个可聚焦元素；全表重绘 | 日常键盘导航冗长。先取消每格独立 Tab，保留可访问的单元格查看，再评估分页或虚拟列表 | Tab 可在有限步骤进入和离开表格；提供方向键或行详情访问全部字段；排序、筛选、显示序号、永久 ID、导出范围不变。分页/虚拟化属于新增能力，单独验证 |
| UI04 / P2 | 截图：处理进度弹窗约 1040px 宽，多行“处理结果”框却只有约 166px | 表单控件宽度规则不完整，长跟进内容难写。多行框随表单内容区伸缩 | 1024×720 下不横向溢出；输入框占可用内容宽度；长中文可换行；保存、取消、历史显示均正常 |
| UI05 / P2 | 截图：记录页空白/标题区域占高度；永久 ID 和每行 5 个操作抢占空间 | 合并工具栏，突出搜索/筛选与记录数；常用操作保留，低频操作归入有文字的菜单；ID 放详情但可查 | 1024×720 可定位搜索、筛选、排序及常用操作；横向滚动时仍可辨认所在记录；删除确认、撤销和编辑入口无丢失 |
| UI06 / P2 | 截图：设置页字段卡片偏高，内外滚动层级多 | 保留现有分区，字段列表与选中字段属性分开；低频规则按需展开，避免增加装饰卡片 | 所有现有选项可找到；未保存离开有明确处理；长表头/多选项可编辑；按钮不被底部遮挡；滚动范围清晰 |
| UI07 / P2 | 截图：分析页长工序名称沿用大号数字样式，窄窗口换行突兀；图表横向滚动 | 数字指标和类别名称分开排版，标题说明压缩；统一色板与图例 | 长工序、空值、单条及多条数据不遮挡；图表可读；统计口径与导出保持一致 |
| ARCH01 / P2 | 静态：renderer.js 约 89KB，混合页面、业务、导出及事件；样式覆盖链长；同步保存整个状态 | 增加渲染/校验/存储接口边界，逐步拆分。同步保存存在增长风险，但本轮 1000 条样本没有证明严重卡顿 | 每次只拆一个职责，原功能回归全通过；保存失败能恢复原状态；性能前后用同一数据集测量。异步化不作为首批装饰改造附带变更 |
| ARCH02 / P2 | 静态：设置分区依赖中文 h3 文本匹配 | 改文案可能改变分组。后续改为稳定 data 属性或组件标识 | 文案变化不影响分组；默认/自定义模板的设置都可访问 |
| DATA01 / P1 | 静态风险：CSV/TSV 整文件读取，未见与 XLSX 同等的文件大小上限 | 大文件可能占用内存，尚未做超大文件故障试验。先加读取前限制和明确提示，再考虑分块 | 超限文件在读取前拒绝；取消不改数据；合法文件、引号/换行/中文/前导零/错误行报告保持兼容 |
| RELEASE01 / P1 | 包内缺测试、构建脚本及原始测试证据；现有构建流程未将测试结果绑定源码校验值，并可替换同名版本包 | 补齐可追溯构建与不可变发布约定，审计包不等于发布包 | 候选 ZIP、源码清单、运行环境、测试结果绑定同一版本及校验值；旧 ZIP 不覆盖；构建可在说明的环境重现 |
| ENV01 / 发布限制 | EXE 未签名；公司电脑实际策略未验收 | 可能影响企业准入；不是当前宿主运行失败。保留便携启动并列明环境要求 | 在目标普通用户账户、离线条件下验证启动、读写、锁定、导入导出；如策略禁止执行，记录阻塞原因，不绕过策略 |

## 已观察但不能冒充缺陷修复的事项

- 深色模式没有实现。它是新增建议，优先级低于输入正确性和列表效率，不宣称原功能回归失败。
- 独立记录详情、分页、批量选中删除没有实现。只有经影响评估后才纳入新增功能，不在继承清单中冒充现有能力。
- 持久诊断日志缺失。若增加，只记录错误码、操作类别、版本及时间，不记录 SN、业务文本、密码或解密数据。
- “玻璃”是已有外观选项。建议用于导航与工具栏，表格/表单保持稳定的不透明底色；这是本项目设计选择，不是要求迁移 Apple 框架。
- 截图中的小窗口滚动较多，但 20 个布局观测均没有页面级横向溢出。表格自身横向滚动不能直接算页面布局失败。

证据详见 [证据索引](证据索引.md)。这些 UI 诊断由程序探针和截图复核产生，尚不是用户现场可用性验收。
