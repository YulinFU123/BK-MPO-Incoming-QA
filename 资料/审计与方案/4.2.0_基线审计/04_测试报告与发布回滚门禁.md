## 排除的测试尝试

1. 初次固定调试端口被系统拒绝绑定，改为系统分配空闲端口后完成运行。失败日志保留，但不计为业务功能失败。
2. 初次性能样本直接注入主进程状态后重载，被原页面 beforeunload 的旧状态保存覆盖。该样本无效，保存为 `ui-audit-invalid-workload.json`，不用于结论。最终采用实际 JSON 恢复入口，并以 1000 条记录断言作为测量前提。

## 候选版发布要求

1. 工作副本与原始基线隔离；每次迭代更新版本、变更、功能继承、已知问题及回滚说明。
2. 候选包含必要源码、配置、资源、测试文件和构建说明；标明运行时来源及校验值。当前包缺失部分是审计发现，不以本报告补齐来冒充已有正式发布能力。
3. 为候选源码/资源和产物生成 SHA-256，将测试报告明确绑定这些校验值。禁止只检查历史日志的 PASS 字样就认定新代码通过。
4. 修复本轮实际失败项；原有回归仍通过；补充取消、输入法、扫描枪、所有列排序、Excel 显示和恢复兼容测试。
5. 在目标 Windows 普通用户、离线、中文路径下实际启动及读写，记录系统版本、缩放、执行策略、人工结论和未验证项。
6. 通过目标验收前只能标为开发版/候选版。未解决的阻塞问题明确披露；“打包成功”不能代替验收。

## 回滚步骤

1. 升级前关闭程序，保留原始 4.2.0 ZIP；从应用导出一份独立加密备份，并确认密码和备份可恢复。不要只依赖每日备份：现行为是本地当天首次保存备份，不保证包含当天最新数据。
2. 新版本在独立目录解压。真实数据路径保持不变，因此验收先用 QA 路径及数据副本；不能同时启动新旧程序竞争写正式 vault。
3. 如新版本异常，关闭新程序，先保留异常现场和升级后的加密数据副本；从原 ZIP 解出旧版并验证校验值。
4. 在隔离副本上确认旧版能读待恢复数据，再恢复正式使用。恢复旧备份会丢失备份后的新增记录，执行前必须核对差异并保留当前副本，不能静默覆盖。
5. 本次 UI 方案不允许变更存储格式。若未来必须迁移，应另行提供双向兼容评估、迁移测试和可逆方案；在此之前不得套用“直接换旧 EXE 即可恢复全部数据”的承诺。

本次交付仅审计文档和证据，不产生需要用户安装的新 EXE。
