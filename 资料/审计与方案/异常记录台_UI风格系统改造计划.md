# 异常记录台 UI 风格系统改造计划

日期：2026-10-26。阶段：设计计划，尚未修改程序或生成新版 EXE。基于已审计的 4.2.0。

## 1. 目标与交互定义

移除侧栏现有“玻璃效果 开/关”入口，替换为“外观与布局”。玻璃保留为一套完整风格，用户能够选择多套 UI 风格，并勾选可组合的外观增强项。

建议采用两层结构：

- 基础风格：提供多套预设，通过带真实组件缩略图的卡片选择，同一时刻应用一套完整视觉方案。卡片同时显示名称和已选标记，不仅显示色块，也不使用长下拉框隐藏差异。
- 外观增强：支持真正的多项勾选，项目之间可以组合。先提供明确、实用且容易验收的少量选项，避免把所有内部样式参数暴露给用户。

这是一项设计建议。互相排斥的完整配色采用单一生效方案；可以共存的视觉特征提供复选项。依据 Microsoft 对单选/复选控件的语义区分，不代表项目必须引入 WinUI。

## 2. 风格目录

| 风格 | 定位与特征 | 表格、下拉与弹窗 |
|---|---|---|
| 专业浅色（默认） | 中性浅灰背景、白色内容、深灰正文、稳重蓝色主操作；强调边界和操作效率 | 较明确的表头层次；下拉实色；弹窗与页面共享字体和状态 |
| 液体玻璃 | 导航和顶栏有克制的透明、模糊和高光；适度增加层次 | 数据区保持稳定实色；浮层优先保证可读性；整套控件适配，不能只改背景 |
| 石墨深色 | 石墨背景、分层深灰内容、较柔和的浅色正文和蓝色强调，适合偏暗工作环境 | 处理表格奇偶行、选中、错误、禁用、图表网格、日期/下拉选择器；不使用简单反色 |
| 高对比 | 实色背景、清楚边框、明显焦点；辅助可读性与复杂显示环境 | 禁用透明和装饰阴影；状态同时有文字/图形；系统强制颜色时优先使用系统色 |

专业浅色候选基础色：背景 #F3F5F7、内容 #FFFFFF、正文 #20242A、次要文字 #5A6572、边界 #CCD3DC、主色 #0067C0。其余风格同样建立完整的语义颜色表，不能只替换主色。所有颜色在实现后测量，不把草案色值当作已通过的结果。

字体延用离线可用的 Windows 中文系统字体。正文约 14px，标签 13px，说明不低于 12px；只保留必要页面标题。间距采用 4/8/12/16/24px；控件圆角约 6–8px。不同风格共享基本布局、图标和操作位置，降低切换后的学习成本。

## 3. 可多选增强项与独立参数

首批复选项：

1. 行间底色：帮助横向追踪同一条记录。
2. 加强表头对比：增强表头与内容区的分界，排序状态更清楚。
3. 强调当前输入：增强当前字段边界与焦点，便于扫码连续录入。
4. 减少动态效果：关闭非必要过渡；系统要求减少动态时自动生效。

独立选择项：

- 信息密度：舒适 / 紧凑，分别控制表格、列表和工具栏间距。输入点击区域仍需足够，不能为了紧凑把下拉按钮缩到难用。
- 字体大小：标准 / 较大；改变字体时同步调整行高和浮层宽度，避免文字裁切。

组合规则必须可解释：高对比模式、系统强制颜色或减少透明度设置会降低/关闭透明效果；“减少动态”优先于主题动画。受限制的选项说明原因并保留用户原偏好，离开限制环境后恢复。必需的焦点可见性、输入校验和错误反馈始终保留，不能作为可关闭装饰。

## 4. 外观面板布局与预览

入口置于侧栏“设置与数据”分组中的“外观与布局”，不在录入页添加新的大标题。

面板布局：

```text
外观与布局                                      关闭

界面风格
[专业浅色 ✓] [液体玻璃] [石墨深色] [高对比]
每张卡片展示：侧栏、字段、展开下拉、表头和一行记录

外观增强                        信息密度 / 字体大小
☑ 行间底色                       舒适  紧凑
☑ 加强表头对比                   标准  较大
☑ 强调当前输入
☐ 减少动态效果

实时预览：SN 输入 / 错误提示 / 下拉 / 排序表头 / 状态

恢复默认                               取消   应用
```

大窗口并列展示配置与预览，小窗口上下排列，保持单一主要滚动区。预览使用明确标注的示例数据，不读取业务字段作为装饰样本。

选择主题可实时预览；“应用”后保存偏好，“取消”、关闭按钮和 Esc 恢复打开面板前的外观。“恢复默认”先改变预览，点击应用才保存。离开或关闭时不默默保存未确认的选择。

切换过程中保留当前页面、字段值、编辑状态、批量扫码队列、搜索/排序和滚动位置。实施时只更新外观变量与属性，不通过重建业务页面切换主题；仍须测试焦点和已展开浮层。

## 5. 实现结构与兼容策略

现有结构：`workspace-ui.js` 创建玻璃按钮，以 `qualityDeskAppearance` 存储 glass/plain；`controls.css` 含玻璃变量及大量固定浅色值，`workspace.css`、`foundation.css` 存在覆盖关系。因此，增加几个主题名称无法解决整体一致性，需要先抽取共享语义样式。

建议新增：

- 主题定义：背景、内容层、边界、正文、次要文字、主按钮、悬停、选中、错误、警告、焦点、图表色、浮层和材质。
- 外观控制模块：读取、验证、预览、应用、取消、恢复、旧配置映射；不包含业务保存逻辑。
- 外观面板组件：主题卡片、复选项、密度、字体和组件预览。
- 组件样式：统一输入、可编辑组合框、原生选择器浮层、菜单、对话框、表格和图表；每类状态有单一明确归属。

具体文件名由实施时的模块边界确定。沿用当前 Electron 和原生前端技术，不增加联网依赖或 UI 框架。

外观偏好采用独立、带版本的配置键，例如 `qualityDeskUIPreferences`；内容包括主题、增强项、密度和字体。校验未知值、损坏数据与存储失败；损坏时采用可用默认外观并给出提示，存储失败不假报“已保存”。

迁移规则：旧 plain 映射专业浅色，旧 glass 映射液体玻璃；无偏好采用专业浅色。旧键保留，只有确认应用后才写新配置，保障旧版回退。业务 vault、数据库/配置格式和数据路径保持原有契约。

软件外观与 Excel 报表样式独立：切换深色主题不会把导出工作簿变成深色；报表继续按固定、适合阅读和打印的专业配色验收。若将来增加报表风格，应作为独立设置设计。

## 6. 分步实施

| 步骤 | 产出 | 工作量与主要风险 | 进入下一步的条件 |
|---|---|---|---|
| A 组件样张 | 四套风格的同一组组件样张，覆盖输入/下拉/表格/弹窗/错误 | 中；仅做背景图易掩盖控件问题 | 每套风格都有完整状态，确认可读性与视觉层级 |
| B 主题基础 | 语义变量、外观模块、浅色与玻璃适配；修复既有回车和对比度缺陷 | 中；旧样式覆盖、浮层漏改 | 原业务回归通过，样式来源清楚，扫描回车不提交且按钮回车正常 |
| C 外观面板 | 新入口、主题卡片、复选增强、密度/字体、预览/取消/迁移 | 中；切换可能丢焦点，配置失败可能误导 | 切换不丢草稿、选择可恢复、配置可持久化 |
| D 全风格适配 | 深色与高对比；所有页面/图表/浮层适配 | 中至高；固定浅色遗漏和组合数量增加 | 四套主题和支持的增强组合通过专项回归 |
| E 候选交付 | 独立工作副本、候选 EXE、源码、清单、变更、截图、测试及回滚说明 | 中；目标公司运行策略仍需实机验证 | 目标验收前标候选版，原始 ZIP 保留 |

建议先把四套样张放在同一组件和同一内容上对比，再进入实现。不能只给风格名称就宣称完成，也不能将简单背景换色作为四套 UI 的验收结果。

## 7. 验收标准

- 旧侧栏玻璃开关已移除；新入口可到达全部主题、增强项和布局选项。
- 四套主题覆盖录入、记录、分析、跟进、设置、登录/锁定、密码、备份、导入映射及各类弹窗；可编辑下拉与原生选择器都纳入。
- 主题切换、预览取消和程序重开不丢失业务数据、草稿或批量队列；按原唯一值、排序、编号和导入导出规则工作。
- 基础主题 × 两种密度 × 1024×720/1280×720/1440×900 做布局检查；字体放大和系统 DPI 另做实机检查。四个增强布尔项的 16 种组合做规则验证，默认/全开/全关及冲突组合做截图与交互复核。
- 普通正文对比度目标 ≥4.5:1；重要图标/焦点/控件边界目标 ≥3:1；透明主题以实际合成背景测量。所有风格的错误/选中状态有非颜色信息。
- Tab/Shift+Tab、Enter、Space、方向键、Esc 和中文输入法有效；系统减少动态/透明与强制颜色行为记录清楚。
- 以同一批 1000 条合成数据比较切换前后耗时和界面响应，排查全表重建和重复事件；本轮仅有基线测量，尚无新主题性能结果。
- 发布文档绑定候选源码及产物校验值；旧版 ZIP 和旧外观配置可回退。没有完成目标公司 Windows 验收前不得标为正式可用版本。

## 8. 设计依据与本次边界

本次实际检查确认现有外观仅为 glass/plain，并查看共享控件样式。以上四套风格、复选项和交互都是新设计计划，尚未实现或测试。

- [Microsoft 单选与复选控件语义](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/radio-button)：互斥项与可组合项采用不同选择行为。
- [Fluent 2 Accessibility](https://fluent2.microsoft.design/accessibility)：层级、焦点、对比度及缩放参考。
- [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：将玻璃材质集中于控制/导航层，节制使用并保持内容清晰。本项目借鉴该层级原则，以现有 Windows/Electron 能力实现相近视觉，不声称使用 Apple 原生材质。

以上官方资料提供原则；四套风格名称、具体数值、增强项、模块安排和发布顺序是本项目方案。
