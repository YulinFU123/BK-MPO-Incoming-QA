# 当前重整方案：理顺功能、BI操作闭环与独立配置文件

更新：2026-11-01。核对基线：0.16.1-dev.1。状态：**梳理方案，尚未实施**。

本次只检查实际路由、BI导入/筛选/导出和配置代码，重写这份规划。程序、版本索引、发布包、业务数据和用户配置不修改；原规划已备份。本文不以代码测试数量替代可用性验收。

## 当前细化规格（2026-11-01）

本方案已细化成[功能与配置实施规格](功能与配置实施规格.md)及[逐项配置总表](配置设计稿/配置项总表.md)：33个旧路由、9个快捷业务动作有明确去向，197个配置项逐项写明默认、范围、位置、依赖和迁移；原BI的48个P参数逐键登记。

进一步明确：应用设置一份、每个工作区设置一份；日周月分别记忆筛选、图表与明细布局。旧安全设置、正式记录和草稿不迁入明文JSON。样例仅作设计，当前0.16.1-dev.1尚不能读取。实施优先级：保存可靠性与配置服务→同页BI闭环→旧能力和公共组件接入→标签效率与版式→目标环境验收。

本轮只新增和完善方案资料，程序、发布版本、业务数据均未修改。

## 工序分视图与文件名日期补充（2026-11-01）

BI分析按“综合不良／自选工序组合／单工序不良”组织，共用完整明细，各自记住日周月、图表和报表。每日文件建议以YYYY-MM-DD命名，来源可明确选择文件名作为主业务日期；旧Work Date来源保持原规则。具体日期冲突、同日更新、覆盖范围及综合率口径见[实施规格第15节](功能与配置实施规格.md#15-综合不良单工序不良与文件名业务日本轮补充)。

本补充仍为设计：现有文件名日期只是补齐功能，不能说新分视图和文件名主日期已实现。

## 2. 收敛后的主导航

主导航只设五项，按工作目的组织：

1. **工作台**：工作区列表、切换和必要的最近操作。
2. **异常记录**：录入、查询、跟进；原扫码、防重复、自定义字段、回收恢复、导入导出继续保留。
3. **BI分析**：一个日常入口，贯通数据来源、筛选、图表、明细和报表导出。
4. **标签设计**：二维码、条形码、文字、批量编号、版式及打印导出共用设计器。
5. **设置**：配置文件管理、字典和分组、备份恢复、外观、低频兼容工具。

“分析与报表目录”“BI工作台目录”“BI自由分析目录”不再并列作为日常起点。迁移期间，尚未接入的旧页面集中在一个“高级与兼容工具”入口，明确列出用途；这不作为永久隐藏独有功能的替代方案。

## 3. BI只保留一条日常操作路线

**添加BI数据 → 自动识别并显示结果 → 修改筛选即更新分析 → 导出当前报表。**

### 首次使用

- 空页面直接显示“选择BI文件”，支持拖入Excel/CSV；旁边提供“使用下载文件夹”。入口就在分析页，不藏到设置中。
- 选择后自动完成扫描、表头候选、日期/数量/工序等识别，原始数据预览和识别结果立即出现。
- 高置信度的已知结构直接沿用；日期存在歧义、数量口径不明确或必要列缺失时，只在本页指出需要处理的项。
- 第一次确实需要人工核对时，使用一个明确动作“开始分析”；不要求依次点击扫描、识别、保存来源、导入四五个按钮。
- 产量是单独标明的数据源类型，默认按日期＋工序＋班次匹配。不良件数与缺陷次数分开，没有有效分母不显示真实不良率。

### 后续每天

- 打开工作区自动读配置，恢复上次数据源与筛选。
- 下载目录有结构兼容的新文件，软件运行期间自动读取、去重并更新；不让用户每天重配字段。
- 改日期、工序、不良项或人员，分析结果和当前报表一起更新。
- 要交付文件时才点“导出报表”；日常操作不出现“保存配置”步骤。

### 一个具体例子

选择下载文件夹 → 日期列识别为Work Date → 选择9月19日、装管、装管反 → 默认显示责任员工数量条形图与对应明细 → 点导出报表 → 预览横向A4标题“9月19日装管反失效人员” → 输出Excel或PDF。

此路线不要求用户先理解“来源、分析方案、图表快照、报告列表”的内部关系。

## 4. 页面布局

```text
┌ 工作区：装管异常     BI数据：已读取…条     配置：已同步       ┐
│ [更换/添加BI数据]  数据日期…  日期列Work Date  [导出报表]     │
├──────────────────┬───────────────────────────────────────┤
│ 筛选              │ 记录条数 / 不良数量 / 产量 / 不良率       │
│ 日期与 日/周/月    │                                       │
│ 工序、班次        │ [分析结果] [原始明细]                   │
│ 不良项、责任员工   │ 默认图表直接显示                        │
│ 报检人            │ 改筛选后自动更新                        │
│ 更多字段…         │                                       │
└──────────────────┴───────────────────────────────────────┘
```

- 数据来源在上方，筛选在左，结果在中间，导出固定在右上；主操作不随滚动消失。
- 日/周/月是同一位置的汇总粒度切换，仍分别记忆条件，不再占三个页面。
- 常用筛选直接可见；其他原始字段收在“更多字段”，支持Excel式搜索、多选、包含、排除和区间。
- “图表类型”“分组维度”在图表旁，默认给出适合当前数据的图，避免空白等待用户拼配置。
- 图表与明细共享同一个有效筛选。显示具体日期范围、数量单位和缺数据说明，所有有效点有数据值和刻度。
- 无数据时明确写“当前条件下0条”，并允许清除筛选；日期未填完整时不销毁输入框和旧结果，用状态说明并阻止误导出。
- 不整页重建表单，不在输入过程中抢焦点；分析进行中显示进度，失败保留用户条件并指出具体原因。
- 打开导出后，在同一上下文展示A4预览和输出选项，保留筛选摘要。窄窗口采用单主区域切换或抽屉，避免硬塞四栏。
- 沿用现有字体和主题，正文14px、辅助12px、4/8/12/16/24间距，以操作和数据层级为主，不再增加装饰图标或重复大标题。

## 5. 生成与保存的职责重新分清

|对象|计划行为|日常是否要点保存|
|---|---|---|
|路径、字段映射、筛选、图表类型、A4版式|修改后自动写入当前配置文件|不要|
|屏幕图表与当前报表|有效筛选变化后自动重新计算和排版|不要|
|要发给别人的Excel/PDF/图片|用户点击“导出报表”生成文件|只有这一步需要导出|
|正式异常记录|仍按业务操作明确登记、编辑和确认|保留必要确认，不把草稿自动提交|

### 报表简化

- 默认报表跟随当前筛选，不再强制“加入图表→切换页面→预览→导出”。
- 常用两种组合：“当前分析一张图”“按所选不良项分别成图”。选择多个不良项时自动按数量排版。
- 标题、纸张、页边距、图表间距、导出格式记住上次设置；标题支持日期/工序/不良项占位符。
- 横向A4优先保持一页；放不下时明确显示页数或调整建议，不静默丢分类。
- 高级拼图和冻结对比图作为低频工具保留，不迫使所有用户走拼图流程。
- 第一次选导出目录后记住，后续按命名规则一键输出；重名自动加序号，不覆盖原文件。只有用户主动“另存到”时再选位置。
- 导出只使用本次有效数据与筛选，不能把上一次图表和本次标题拼在一起。

## 6. 独立、可替换的配置文件

这是本次用户明确提出的新约束，后续迁移以此为准。

### 文件形式

- 一个工作区绑定一个明确可见的`工作区名称.settings.json`，例如`装管异常.settings.json`；文件存放在用户可写的配置目录，可选择位置。
- 同一文件内按模块分区：BI路径/映射/筛选/图表/报表、异常记录界面偏好、标签模板与布局等。不同工作区分别绑定，互不覆盖。
- 配置中心只保留必要操作：查看当前文件位置、切换配置文件、恢复上次有效配置；“另存副本”等低频动作收在更多菜单。
- 文件只装设置、映射、规则和布局，不混入正式业务记录、未提交录入草稿、登录密码或恢复密钥。

### 自动写入与替换生效

1. 普通配置修改自动保存，状态显示“同步中/已同步/未同步”，正常状态不常驻一个“重试保存”按钮。
2. 在文件夹直接替换当前JSON后，程序自动检测，完整读取并验证，再一次性应用；无需重新启动、重复导入配置或点击应用。
3. 更改筛选、标题、图表时立即刷新相应区域；来源或字段口径改变时在后台重新准备派生分析，完成前明确显示正在更新，原始文件和正式记录不改。
4. 字段缺失或路径不可读时指出具体项，不把不兼容设置静默套到旧结果上。
5. JSON损坏、缺少必要字段、写到一半或版本不支持时保留上次有效配置，不清空、不覆盖原件；提示文件名、原因和恢复入口。
6. 程序自己写入配置时避免反复触发自身重载；外部替换与内部保存撞车时通过修订及内容校验保护，不让旧的待保存内容覆盖刚替换的文件。
7. 替换配置只改变当前工作区设置，不改变工作区身份，不复制或提交正式业务记录。

### 保证配置只有一个权威来源

迁入外部文件的设置，以该文件为权威；旧加密SQLite、标签记忆及旧BI配置通过适配器只读继承并保留回退，不维持两套会互相覆盖的长期配置。未迁移模块明确列出，不能宣称整合完成。

现有Windows保存故障仍开放。配置文件服务必须独立验证写入失败、占用、冲突和恢复，不能直接照搬存在失败的写法，再以正常路径测试通过当作可靠。业务库保存故障继续作为正式发布阻断项。

## 7. 旧功能去向与合并规则

|现有入口/能力|调整去向|处理要求|
|---|---|---|
|BI工作台、BI自由分析|一个“BI分析”入口|统一操作路线与当前数据范围|
|历史数据与字段、新来源编辑|数据源设置，日常在分析页选择数据|自动识别与字段修正复用一个组件|
|日报处理、历史趋势、日周月|同页的来源与汇总粒度|原处置状态等独有筛选必须保留|

|历史完整Excel、历史图表、A4报告|统一“导出报表”入口下的输出模板|不同报表的独有内容不可在合并时省掉|

|异常表头、规则、唯一值、草稿与跟进|异常记录及其字段设置|原业务流程和数据兼容保护|

合并以实际功能和统计口径等价为前提。尚未逐项验证的独有算法先在兼容入口保留，迁移后才收起旧界面，不用新空壳替换旧功能。

## 8. 代码职责整理

沿用Electron、原生界面和现有本地Python分析，不新增桌面框架。

- **配置文件服务**：文件选择、校验、自动写入、外部替换监测、版本迁移、最后有效快照。
- **数据来源服务**：文件/文件夹读取、识别、批次和去重，统一输出来源状态。
- **统一查询服务**：一个有效查询对象驱动图表、明细、分母和导出，取消与迟到响应按代次管理。
- **报表服务**：读取当前有效查询与版式生成报告，独立控制进度、快照和输出文件。
- **BI页面组件**：来源栏、筛选栏、结果区、导出面板分别管理展示与交互，不各写一套规则。
- **旧能力适配器**：接入旧BI、原异常及标签设置，避免在界面事件里直接读写多个配置文件。

现有统计公式、独立码表和数据保护逻辑先复用，重构针对职责和状态链路。原加密业务仓储不随界面整理就地迁移。

## 9. 推进顺序与验收

|顺序|交付内容|必须看到的结果|
|---|---|---|
|当前：梳理|本方案及旧入口去向|明确重复入口、独有能力、完整流程和配置文件职责；不改程序|
|第一步：配置底座|独立文件与兼容读取|修改后自动写、重启恢复、外部替换自动应用、坏文件不清空、工作区隔离、旧配置不被覆盖|
|第二步：BI最小完整闭环|同页导入→筛选→自动图表→导出|一个真实本地文件从首次读取走到可打开的报表，用户无需寻找保存配置按钮|
|第三步：入口与旧能力收敛|统一导航、复用组件、原BI能力迁入|独有功能继承清单逐项核对；日常菜单不堆14个页面；异常和标签不回退|
|第四步：整机验收与交付|目标Windows、设备、历史数据、回滚|从实际页面完成工作流；旧保存故障需解决或持续阻断正式发布；只保留明确当前/上一入口|

### 场景验收优先

1. 第一次打开，能够直接找到选择BI文件；导入后知道读取了哪份文件、哪个日期列、多少数据。
2. 选择“装管反”和指定日期，图表、明细、报表中的人数与数量对应。
3. 在此基础上导出横向A4，文件路径清楚，Excel/PDF实际打开检查，不额外保存配置。
4. 关闭后重开，路径、筛选、图表及版式恢复。
5. 软件运行中替换当前配置文件，指定设置自动应用；不改正式记录。
6. 配置写到一半、损坏、缺失、占用或新旧冲突时，保留有效设置和原数据，显示可执行的恢复办法。
7. 切换两个工作区，各自配置不串；新BI文件自动读取后，日报/周/月以及报告使用同一范围。
8. 原异常录入、防重复、跟进、导入导出、标签二维码/条形码均继续可用。

代码测试负责算法与保护逻辑；实际操作验收负责能否看懂、找到入口和完成任务。组织策略限制下没有完成实际界面验证的项目，必须保持未验收，不通过其他隐藏入口绕过，也不以测试数量替代。
